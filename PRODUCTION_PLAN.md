# ChatGPT Conversation Archiver — production plan

## Состояние
Репозиторий: `Naeirae/ChatGPT-Conversation-Archiver-production`.
Ветка разработки: `production-v0.4.0-build`.
База: production собран на стабильной бесплатной ветке и синхронизирован с исправлениями free до 0.3.50; поверх неё работает отдельный платный контур.

## Архитектурный принцип
Production-версия не требует собственного пользовательского сервера.

- Содержимое чатов не передаётся разработчику.
- Архивы и незавершённые проходы хранятся локально в Chrome.
- Google Docs используется через сессию Google самого пользователя.
- Google-авторизация нужна только для действий пользователя с его Google Docs и не используется как аккаунт Архиватора.
- Собственная база пользователей, email/телефоны/ФИО и серверная аналитика не требуются.
- Лицензия проверяется локально по криптографически подписанному ключу.
- В расширении хранится только публичный ключ проверки. Приватный ключ выпуска лицензий в репозиторий и сборку не попадает.

## Бесплатный старт
- Первые **5 успешно завершённых сохранений чатов** — бесплатно.
- Длина чата сама по себе не расходует дополнительные сохранения.
- Неудачный или незавершённый проход не расходует сохранение.
- Повтор того же завершения по тому же job id не списывает сохранение дважды.
- Пустое продолжение без новых сообщений не расходует сохранение.
- Просмотр, копирование старых архивов, сверка и добор изображений не расходуют сохранения.
- После исчерпания лимита старые архивы и документы остаются доступны.

Бонуса **+5 за публикацию нет**: он исключён, чтобы не вводить ручную проверку соцсетей и лишний контур пользовательских данных.

## Платные лицензии
Стартовые варианты:
- **249 ₽ — 30 дней**
- **1 790 ₽ — 1 год**
- **3 490 ₽ — бессрочно**

Лицензионный ключ содержит только технические сведения: идентификатор лицензии, тип плана, дату выпуска и, для срочной лицензии, дату окончания. Персональные данные в ключ не включаются.

Срочная лицензия перестаёт разрешать новые сохранения после даты окончания. Бессрочная лицензия срока окончания не содержит.

## Выпуск лицензий
Лицензии подписываются офлайн приватным ключом ECDSA P-256.

Инструмент выпуска: `scripts/license-tool.mjs`.

Пример:
```
node scripts/license-tool.mjs --key /safe/path/private-key.pem --plan monthly
node scripts/license-tool.mjs --key /safe/path/private-key.pem --plan annual
node scripts/license-tool.mjs --key /safe/path/private-key.pem --plan lifetime
```

Приватный ключ должен храниться отдельно от Git, сборки расширения, лендинга и пользовательских устройств.

## Ограничение безсерверной модели
Подписанную платную лицензию подделать без приватного ключа нельзя, но **локальный счётчик пяти бесплатных сохранений нельзя сделать полностью защищённым от намеренного сброса пользователем без внешнего авторитетного состояния**. Для первого релиза принимаем это как ограничение безсерверной модели; не описываем локальный лимит как технически неустранимую защиту от обхода.

## Что доступно без активной лицензии после исчерпания лимита
- уже сохранённые архивы;
- копирование и просмотр старых архивов;
- ссылки на уже созданные Google Docs;
- локальная библиотека;
- справка и диагностика;
- удаление локальных данных.

## Что блокируется после исчерпания лимита
- новый полный сбор;
- продолжение завершённого архива с созданием нового результата;
- восстановление/продолжение по Google Doc, если оно создаёт новый завершённый результат.

Незавершённый технический проход, начатый при доступном сохранении, должен оставаться восстанавливаемым.

## Что уже реализовано в ветке
- production-код синхронизирован с актуальными UX/recovery-исправлениями free до 0.3.50;
- боковое знакомство без затемнения, со сворачиванием Help/Settings перед запуском;
- recovery-checkpoint сохраняется по ходу хронологического прохода, поэтому закрытие рабочей вкладки не должно терять незавершённый сбор;
- локальный счётчик пяти бесплатных успешных сохранений;
- fail-safe: неудачные проходы кредит не расходуют;
- UI остатка бесплатных сохранений;
- локальная активация подписанного лицензионного ключа;
- проверка срока срочной лицензии;
- офлайн-инструмент выпуска лицензий;
- отсутствие публичного GitHub-updater в production-сборке;
- единая проприетарная лицензия и отдельное уведомление о правообладателе.

## RU payment backend

Подготовлен минимальный Cloudflare Worker для российского контура оплаты через Robokassa:

- checkout для monthly / annual / lifetime;
- фиксированные суммы 249 / 1 790 / 3 490 ₽;
- подписи Robokassa SHA256;
- проверка ResultURL по Паролю #2 и сумме заказа;
- выдача license token только после подтверждённого ResultURL;
- KV хранит только техническое состояние заказа и готовый ключ;
- содержимое чатов в платёжный сервис не передаётся;
- success-страница показывает ключ для вставки в production extension;
- для НПД предусмотрено подключение Робочеков СМЗ, но Receipt не зашит до проверки настроек конкретного магазина.

Код: `payment-worker/`.

Для live-test нужны внешние настройки, которых в Git быть не должно: MerchantLogin, тестовые Пароли #1/#2 Robokassa, KV namespace, приватный P-256 JWK и публичный URL Worker.

## Landing / GitHub Pages / payment onboarding

Публичный лендинг опубликован через GitHub Pages из `/docs` ветки `production-v0.4.0-build`:
`https://naeirae.github.io/ChatGPT-Conversation-Archiver-production/`.

Текущий лендинг:
- переработан в коммерческую композицию с акцентом на функции продукта;
- убраны англоязычные внутренние формулировки из пользовательского текста;
- первый экран показывает сбор длинного чата, продолжение архива и Google Docs;
- добавлен реальный скриншот интерфейса расширения;
- тарифы 249 ₽ / 30 дней, 1 790 ₽ / год, 3 490 ₽ бессрочно опубликованы;
- favicon и брендовые изображения подключены из актуальной иконки расширения;
- SEO-текст строится вокруг сохранения длинных чатов ChatGPT и Google Docs;
- конфиденциальность вынесена в короткое пользовательское пояснение и отдельную страницу privacy.html;
- старый полный юридический вариант сохранён как legal.html, чтобы не потерять условия, возврат и реквизиты продавца;
- тексты не обещают непроверенную 100% полноту гигантских чатов.

Основание позиционирования: в публичных обсуждениях пользователи жалуются на общий JSON-экспорт, неполные длинные выгрузки и необходимость вручную подгружать старые сообщения у части exporter-расширений. Дифференциаторы Архиватора: проход длинного чата с подгрузкой, recovery checkpoint, продолжение архива по подтверждённому стыку, локальная обработка и Google Docs.

Robokassa не подходит как основной контур: форма требует банковский счёт резидента РФ, а продавец — гражданин Казахстана с российским НПД. Текущий кандидат — Prodamus. В анкете выбрана категория «Услуги → IT → ПО/Лицензии», онлайн; сайт и тарифы готовятся к проверке Prodamus. Перед интеграцией нужно получить подтверждение подключения при таком статусе продавца и доступ к платёжным уведомлениям.

Checkout-ссылки добавлять после одобрения платёжного контура и проверки автоматической выдачи лицензионного ключа.

## Chrome Web Store

Начата подготовка публикации. Актуальные требования Google: заполненные Store listing и Privacy, минимум один screenshot, иконка 128×128, двухэтапная проверка аккаунта разработчика. В карточке нужно явно сообщить о платной модели, потому что после 5 бесплатных сохранений новые сохранения требуют лицензии.

Перед отправкой на модерацию отдельно проверить минимальность permissions и подготовить точные обоснования в Privacy tab. `debugger` оставляем: на нём держатся физическая прокрутка длинного чата и операции копирования/вставки в документ; это обязательная часть основного сценария расширения, а не запасной доступ. Остальные permissions — scripting, tabs, storage/unlimitedStorage, offscreen, clipboardRead/clipboardWrite — также сверить с фактическим кодом и описать по назначению.

## Перед релизом
1. Прогнать CI после текущих изменений.
2. Собрать production build и установить его как отдельное распакованное расширение.
3. Live-test: 1–5 успешных сохранений, шестой запуск, неудачный проход, восстановление незавершённого прохода.
4. Live-test: валидная срочная лицензия, истёкшая лицензия, бессрочная лицензия, повреждённый ключ.
5. Проверить Google Docs в production-сборке отдельно от лицензирования.
6. Проверить длинный чат и многочастный Google Docs export; не обещать на лендинге непроверенный предел размера.
7. Подключить оплату так, чтобы платёжный провайдер не требовал от Архиватора собственной пользовательской БД.
8. После выбора способа оплаты отдельно проверить фактический поток персональных данных.
